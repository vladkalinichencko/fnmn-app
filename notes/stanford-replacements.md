# Stanford dead-lecture replacements

322 `status=unavailable` rows with real titles from `playlists.csv` (15 Stanford playlists), matched against current official Stanford playlists.

## Headline finding (read first)

- **None of the 322 videos are actually gone.** Every single original ("dead") URL was re-checked on 2026-09-24: `yt-dlp --skip-download` reports `availability=public` with a proper title for all 322, i.e. they all still play on youtube.com.
- What *is* broken is **oEmbed**: all 322 originals return **HTTP 401 Unauthorized** from `https://www.youtube.com/oembed?url=<video_url>&format=json`. Spot-checked brand-new public Stanford lectures (CS229 Spring 2026, CS224N Spring 2024, CS221 Autumn 2025, CS231N 2025, CS336 2026) also return 401 while `yt-dlp` reports them public, so 401 here means **embedding disabled by the owner**, not deletion. Whatever marks rows `unavailable` in `playlists.csv` appears to track embeddability, not watchability.
- Consequence: there are almost no true "re-uploads under new URLs" to find. **Zero** dead titles have an exact-title counterpart under a different video ID in any candidate playlist. The one genuine new playlist found by search (CS224W "... I Jure Leskovec") shares 39 of 47 video IDs with the old CS224W playlist — same videos, not re-uploads.
- **5 videos got a verified same-topic counterpart** (all CS336 Spring 2025 lectures re-recorded with near-identical titles in Spring 2026, all `yt-dlp: public`). Everything else is `needs-eyes` (a plausible same-topic video exists but lecture numbers/topics differ enough to need a human) or `no-counterpart` (1 row).
- Practical takeaway for repair: the original URLs still work for watching; if the app needs *embeddable* videos, only oEmbed-200 videos qualify — among all 346 IDs checked (dead + candidates), only 4 returned HTTP 200 (EE364A L1 `kV1ru-Inzl4`, CS229-2022 L1 `Bl4Feh_Mjvo`, CS224N-Winter2021 L1 `rmVRLeJRkl4`, CS224W-2021 L1.1 `JAB_plj2rbA`).

## Method

1. Extracted all `status=unavailable` rows with real titles (skipped blank/`[Private video]`/`[Deleted video]`) for the 15 Stanford playlists: **322 rows**.
2. Web search per course for the current official Stanford playlist (Stanford Online channel preferred, newest year). Results in the table below; 19 unique playlists total (15 originals + 4 newer offerings: CS224W, CS221-2025, CS224N-2024, CS336-2026; CS229-2026 was already in the CSV).
3. Fetched every playlist with `yt-dlp --flat-playlist -J` (no download), sequentially with sleeps, on 2026-09-24. All entries resolved with IDs + titles (no private/deleted placeholders).
4. Fuzzy-matched (normalized titles, `difflib.SequenceMatcher`) each dead lecture against the current listing of its own playlist plus the newer-offering playlist, excluding the identical video ID. Lecture-number conflicts (e.g. dead "Lecture 2" vs candidate "Lecture 12") force `needs-eyes`, never `replaced`.
5. Verified every dead URL and every cited candidate two ways: YouTube **oEmbed** (recorded per row; HTTP 200 = embeddable+live) and **`yt-dlp --skip-download` availability** (recorded per row; `public` = watchable on youtube.com). No URLs were invented — every replacement URL is a real video ID taken from an official playlist listing.
