# Dia local sources on macOS

Проверено 24 сентября 2026 года на локальном профиле Dia. Исследование не выводит и не сохраняет пользовательские URL, названия страниц или содержимое вкладок.

## Что читается напрямую

У каждого обнаруженного профиля есть файл:

```text
~/Library/Application Support/Dia/User Data/Profile */Bookmarks
```

Это валидный UTF-8 JSON Chromium bookmark tree, версия `1`. Верхний уровень содержит `checksum`, `version` и `roots`; в `roots` есть `bookmark_bar`, `other` и `synced`. Узлы имеют стандартные типы `folder` и `url`:

- folder: `children`, `id`, `guid`, `name`, `date_added`, `date_modified`, `date_last_used`;
- url: `url`, `id`, `guid`, `name`, `date_added`, `date_last_used`.

На текущей машине найдены `Profile 3`, `Profile 4` и `Profile 5`. В каждом по 17 папок; в них 233, 233 и 234 URL-узла соответственно. Максимальная глубина дерева — 3. Имя профиля дополнительно хранится в `Profile */Preferences` как `profile.name`; экспортёр может использовать его вместо номера каталога.

Следствие: bookmarks, folders и вложенность можно выгрузить полностью без запуска Dia и без доступа к зашифрованным хранилищам. Сохранять нужно профиль, источник `dia_bookmark`, путь папок, название, URL и Chromium IDs/GUIDs. Один URL нельзя дедуплицировать глобально: профиль и путь являются частью происхождения записи.

## Что не читается как обычная SQLite база

В каждом профиле есть:

```text
tabs.db
live_data_database.db
```

У `tabs.db` на текущей машине размеры различаются по профилям; первые 16 байт не равны SQLite magic header `SQLite format 3\\000`. `sqlite3 .tables` не возвращает таблиц. В бинарных данных нет обнаруженных маркеров `http://` или `https://`; доля печатных байтов около 38%, что согласуется с бинарным/зашифрованным форматом. `live_data_database.db` ведёт себя так же. Поэтому эти файлы нельзя безопасно трактовать как SQLite, LevelDB или JSON без обратной разработки формата.

Бинарник установленного Dia содержит строки `GRDBSyncMetadataStore`, `Sync_DiaTabGroupData`, `KeychainClient` и типы `TabGroup*`. Это подтверждает наличие собственного GRDB-связанного слоя, sync-моделей таб-групп и Keychain-интеграции, но не раскрывает схему и ключи. Официальная страница безопасности Dia заявляет, что bookmarks, history и files по умолчанию шифруются и хранятся локально, а при Sync данные end-to-end encrypted. Наблюдаемый `Bookmarks` в этой установке при этом читается как обычный Chromium JSON; это фактическое свойство текущего файла, а не доказательство того, что все локальные данные Dia хранятся в открытом виде.

## Что это значит для полного импорта

1. Bookmarks можно импортировать файловым адаптером полностью, включая профили и папки.
2. Таб-группы, открытые вкладки и закрытые группы нельзя считать покрытыми только по `Bookmarks`: в официальных release notes они описаны как отдельная сущность, а их локальное состояние находится в бинарных `tabs.db`/live-data хранилищах.
3. Для таб-групп нужен один из двух проверяемых путей: официальный экспорт/копирование URL из интерфейса Dia или исследование живого протокола/внутреннего API при запущенном Dia. Чтение файлов «на месте» без ключей и схемы сейчас не даёт надёжного результата.
4. Если нужен источник-группировщик уже выгруженных ссылок, у bookmark-записей доступны профиль и полный путь папок. Для Reading List отдельный адаптер уже может сохранять `reading_list` как источник; для tab groups понадобится отдельное поле происхождения, когда появится доступ к данным.
