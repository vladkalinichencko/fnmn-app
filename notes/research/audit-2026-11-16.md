# Codebase audit — 2026-11-16

Nine read-only review agents over `App/REED`, `Sources/REEDCore`, `App/Activity`, `App/Share`, and `server/`: two-pass review (bugs/correctness + maintainability) per side, implicit state machines per side, architecture/style vs `coding`+`architect` skills per side, SwiftUI performance, UX path audit, and battery/thermal. Every agent read `AGENTS.md` as its rubric. Parent verified the highest-impact claims against source; status is marked per finding.

## Verified by parent (read the code)

- **`server/adapters/pdf.py:86-94` — `_step` can deadlock permanently.** `Popen(stdout=PIPE, stderr=PIPE)` then `while process.poll() is None: sleep(2)`; pipes are only drained by `communicate()` after exit. A child that writes ~64 KB to stderr (tqdm, MLX warnings) blocks on write and never exits; the poll loop never ends, and the module-level `_OCR` lock stalls every later PDF/arXiv import. Fix: redirect to files or drain pipes on a thread.
- **`server/digest/refresh.py:69-74` + `instagram.py:47` — `/digest/refresh` cannot succeed for Instagram (same shape for Telegram).** `_collect` builds a fresh `Store()` over the same `posts.jsonl`, so `known` already contains the post being refreshed and `collect` skips it; three attempts then `ValueError`. Only X works because `digest/x.py` does not filter by `known`.
- **`App/REED/Library/ItemTile.swift:164-169` — "Mark as Read" also archives.** Fires `.setRead` and `.setArchived(!isRead)`; the item vanishes from Library/Continue/albums, and "Mark as Unread" unarchives items the user archived deliberately. `APP_SPEC.md` says archive is a separate catalog fact; a separate Archive menu item already exists at :181-183.
- **`App/REED/Store/ImageFiles.swift:24` — `headerSize` returns `width × width` for every non-rotated image.** Found independently by four agents (two-pass, UX, perf, arch). Skews aspect/scale math for all upright covers and article images.
- **`App/REED/Store/LibraryModel.swift:117-128` — buffered `savePosition` is journaled nowhere when a non-place change lands inside the debounce window.** The `default` branch folds `places` into `progress`, journals deferred `.open/.openGroup` but explicitly `continue`s on `.savePosition`; `places` is already cleared so `foldPlaces()` later sees nothing. Position saves locally, other devices never get it.
- **`server/service.py:111-116` — `/jobs/{id}/file` serves any done job's file as `video/mp4`** with no `kind` guard, unlike `/package` at :72 which excludes `videoFile` (and here it is inverted: `/file` should probably require `kind == "videoFile"`).
- **`server/digest/reading.py:87-102` — `page_fetch` fallback shape is inverted vs production.** Real `reader.Tab` has `.fetch`; the `tab.context.request` fallback exists only for test fakes, which implement `.context` but not `.fetch` — so tests exercise the fallback and production `tab.fetch` is untested. Second code path that exists only for a fake.
- **`Sources/REEDCore/DigestSettings.swift:73` — `hours` decodes as bare `[Int]`**; UI sorts positionally (`DigestSettingsSections.swift`), so on-disk `[20, 8]` silently relabels Morning/Evening, and padding invents values the user never saw.

## High-confidence findings (agent-verified, code read; runtime behavior reasoned)

### Server — correctness

- `reader.Connection.events` is shared across all tabs; `Tab.goto` clears it and `document_status` scans cross-tab traffic — concurrent jobs on one profile can read each other's HTTP status (`server/reader.py:94-167`).
- WebSocket failures escape `ReaderError`; `Tab.close` catches only `ReaderError`, so a dead socket in `job()`'s finally skips `_release` — refcount never drops, headless Chrome leaks (`reader.py:96-114, 328-337`).
- Headed launches bypass `_SESSIONS` and delete `SingletonLock`/`DevToolsActivePort` unconditionally; service process and monitor are separate launchd agents, so a `digest.login` can fight a running headless Chrome on the same profile (`reader.py:277-315`).
- `jobs.py`: dedup requires `error is None`, so done-degraded jobs respawn on every retry and accumulate; `forget()` on a running job leaks the eventual archive; failed uploads keep `job.upload` bytes forever; `phase`/`stage`/`done`/`total` are written off-lock while `submit`/`status` read under `_LOCK`.
- `adapters/x.py`: `httpx.HTTPError` from `tab.fetch`/`web.bytes` is not caught by the `(ReaderError, OSError)` guards — one dead image aborts the whole thread import.
- `digest/reading.py:120-131` + `web.py:27-30`: video/photo bodies are fully buffered before the 400 MB check — a hostile CDN URL can exhaust memory.
- `monitor._run`: `SOURCES[source["network"]]` lookup is outside the try — one bad `subscriptions.json` entry kills the whole run before statuses are written.
- `arxiv.py`: 40 MB cap is on the compressed tarball; `gzip.decompress` is unbounded.
- No request-size limit on `/files` and `/jobs`; bearer check uses `!=` not `hmac.compare_digest`.
- `Store.posts()`/`append()` reparse the whole `posts.jsonl` per call — monitor does it per source, build does it repeatedly; quadratic in store size.
- `youtube.download` only accepts `{name}.mp4`; yt-dlp can pick another container → false `ImportFailure`; `.part` files leak on failure.
- `digest.telegram` `_UNREAD_COUNTS`/`_UNREAD_DONE` globals are "once per monitor run" but the FastAPI service is long-lived — first refresh freezes unread counts for the process lifetime (also flagged by arch review as state scoped to the wrong lifetime).
- `jobs.py`/`digest` post lifecycle is file-inference: crash between `_write` and `record_build` re-ships posts; `post_ids ∩ skipped` conflation; `_available` mutates `post.media` in memory only.
- `pdf-book/` pipeline state = which output files exist; `run-formula-ocr.py` pops override keys so permanently-bad formulas re-run forever; `run-footnote-ocr.py` can store `""` which suppresses the issue but emits no definition → validation fails the whole import.
- Digest package.json media paths (`post.media[].path`, `video.*`, avatars) are never validated — `Digest.url(of:)` joins blindly; `../` escapes the digest folder inside the container (client-side, see below).

### Client — correctness / UX

- Stale async completions are unfenced: `ItemScreen`'s `.task(id: textDigest)` can be replaced by an older task finishing last (old package silently overwrites fresh content); `previewedOriginal` latch races two quickLook downloads — same shape `WebGeneration` was built to fix.
- `WindowNavigation` has three parallel "route waiting" latches (`pending`, `pendingItem`, `digestPost`) consumed by two `onChange` handlers — two deep links in the same launch window silently drop one; `digestPost` never clears if the post never arrives, and hidden posts still reach the widget → dead scrollTo.
- `VideoReaderView` `.coming(file)`: failed iCloud download leaves an eternal spinner — `.task(id:)` doesn't restart for an unchanged id; plus generic `catch` reports `CancellationError` as a failure alert when leaving mid-download.
- Digest "Hide" is one-way (no unhide UI; recovery = delete `digests.json`); hidden posts still appear on the widget; digest media-retry failure is invisible once any digest exists.
- Settings "Save" persists the server connection to Keychain *before* `check()` — a failed check leaves the unverified connection active.
- Deleting a collection from inside its screen leaves a phantom `AlbumScreen` whose Rename/Delete no-op.
- One alert title "Couldn't save the change" covers sync failures, corrupt packages, iCloud download failures, album-name errors.
- Shelf shows `Color.clear` while `.settling` — blank tab on fresh install/empty shelf during sync.
- `sendAfterMenu` 350 ms uncancellable `Task` can hijack dialog state — tap Delete then another menu item within 350 ms and the delete confirmation replaces the just-opened sheet (found by two agents).
- `ReaderState.keepsPlace` never clears except on `.speedRead` — opening from an annotation pins `place` at the note's piece for the whole session; every save writes the stale position. Needs owner intent check.
- `LiveCropWebView.Coordinator.loaded` keys on URL only, ignoring `selector` (latent — inputs are currently fixed).
- Empty-document items (`.link`/`.file` with `blocks: []`) reachable via search hits and `reed://item` deep links bypass `ItemTile.open`'s Safari routing → blank reader + `savePlace` computes `+inf` progress → `JSONEncoder` throws → repeating "Couldn't save" alert.
- `LibraryModel.reindex: Task?` is written, never read/cancelled — overlapping `syncWithOtherDevices` can stack `reindexSearch` tasks.
- `DigestModel`: `deliveryFailed`/`lastError`/`pendingDownloads` are three fields for one outcome and can disagree; `loaded` vs `state` overlap skips the `.loading` transition on retry; `refreshed` media never invalidates on re-sync.
- `ImportActivity.end(status:)` decides success by `status == "Ready"` string — `.dismiss`/`.deleted` report success to the BG task.
- Minor: `reed://item` drops `seconds`; `reed://continue` with nothing to continue is silent; item failure state has no retry; annotation delete has no confirmation while item delete does; "Ask ChatGPT" has two inconsistent destinations (`?q=` URL vs bare `chatgpt://`); digest Morning/Evening pickers can silently swap (see `hours` above); debug `print` left in `PostParts.swift:13` and `ReaderSettings.swift:373`; widget deep-link fallbacks name a different destination.

## Performance (SwiftUI hot paths)

Sync:
- Every `.active`/pull-to-refresh runs the full 4-stage sync; each delivery → `LibraryModel.write` → full `articles.json` + `state.json` encode, `refreshQueries()` rebuild (locale sort over whole catalog), and a widget reload — N deliveries = N of each. Fix: batch per sync pass.
- `logLocalState` writes ~1 os_log line per material per sync (~1,500 for a large library).
- Journal sync pre-downloads the whole `state/` iCloud folder then re-reads each entire `.jsonl` per sync — should track byte offsets, drop folder pre-pass.
- `changedDeliveries` stats every delivery file per sync; unknown files get `materialHead` reading up to 4 MB (can trigger iCloud download).
- `ServerClient.finished` polls with no deadline; `repeatingDrops` restarts multi-hundred-MB downloads from byte zero on transient errors; `URLSession.shared` has no `waitsForConnectivity`/cache/background session.
- `DigestModel.sync` decodes every digest `package.json` up to twice per sync, on every `.active`/folder change/refresh.
- Widget refresh fires per `library.snapshot` change (debounced 2 s) — reloads widget timelines repeatedly through a long sync.

Scroll/reading:
- Per-frame chain: `onGeometryChange` on every `BlockView` → `reader.rowChanged` mutates `@Observable rows` → `ReadingLineView` recomputes `stops(of:)` = `textLines.filter` over all article lines, per frame. Same class for `shown`/`textLines` mutations.
- Every scroll-visibility change re-evals all of `ReadingSession.body`: `marks` = `Dictionary(grouping:)` over all annotations, `findsByBlock`, `visibleBlocks`, `readShare` per block.
- `PlateView` runs full Markdown→AttributedString `plainText` parse per body eval — including per frame during the note pan (`drag` is `@State` per pan frame).
- Every plate carries `GeometryReader` mask + `.glassEffect` + `HorizontalPan` recognizer + unconditionally-built `MarginNote` (with two-gradient mask even when inactive).
- Position saves debounce to a full `progress.json` rewrite ~every 2 s of quiet while scrolling.
- `LibraryQueries.item(_:)` is O(catalog) `first(where:)` called per search-result row; `snapshot.articles.contains/first` scans in `ItemScreen` body and `.task(id:)`.
- Five in-body catalog searches (album/group/source/archive/annotations + digest search) fold every item's `searchText` per keystroke, no debounce, main thread.
- `ArrangedItems` re-sorts with `localizedStandardCompare` per body eval.
- `Annotation save → refreshQueries()` rebuilds the entire catalog projection on the main actor for changes that only affect `annotationGroups` — on the annotate-while-reading path.
- `ShelfScreen.annotatedIDs` rebuilds `Set(annotations)` inside a per-hit predicate — O(hits × annotations).
- Speed reader recomputes section heading (backward block scan + Markdown strip) per word frame; reading-line drag does `textLines.filter` per visible block per call.
- `VideoReaderView` wraps screen+transcript in `GeometryReader`; cue ticks re-lay out captions; `anchorPreference`→`GeometryReader` highlight redraws per preference change.
- `LiveCropView` = full `WKWebView` per interactive figure with live `ResizeObserver`; `shownHeights` is an unbounded static dict.
- `.scrollEdgeEffectStyle(.soft)` on TabView adds compositing to all scrolling.
- First-scroll image decode burst (cached thumbnails mitigate); `AlbumFan` is the heaviest tile.

## Implicit state machines — summary

Server: `jobs.py` import job (`phase`+`error`+`kind`+progress, written off-lock); digest post lifecycle spread across `posts.jsonl`/`builds.jsonl`/files-on-disk; `monitor.py` per-source status + transient `retryable` side-channel; `reader.py` browser sessions (`_SESSIONS` refcount vs `DevToolsActivePort` vs `process is None`, headed bypass); `pdf-book` pipeline state = filenames; `telegram.py` unread state across CLI + globals + counters; `prepare_browser_library.py` readiness across tars + `errors.json` + two id namespaces.

Client: `ArticleOpener.text`/`previewedOriginal` unfenced async latches; `WindowNavigation` three route latches; `VideoReaderView.downloading`+`source` with no failed state; `LiveCropWebView.loaded` ignoring selector; `sendAfterMenu` uncancellable timer; `places`+`progressUnsaved`+`progressWrite` progress outbox; `DigestModel` delivery outcome trio + `loaded`/`state` overlap + `refreshed` cache; `ReaderState.keepsPlace`; smaller: `MediaViewer.image` conflates loading/failed, `ImportActivity.end` string status, `RouteStack` debounce (borderline-OK), `ServerLink` lazy latch (deliberate).
